# Database tables (D1)

A reference of the D1 tables and the columns agents most often need, with the migration that added them.
Migrations live in `worker/src/db/migrations/` (numbered `NNNN_name.sql`; CI applies them on deploy).
The schema itself is the source of truth — when this list and a migration disagree, the migration wins.

### Database Tables
- `users` - User accounts
- `auth_sessions` - Sign-in sessions (the id is the Bearer token; 30 days, sliding — renewed while in use) · `auth_codes` - one-time sign-in codes (migration 0129; see "Sign-in & sessions")
- `decks` - Vocabulary decks; `decks.source_key` (migration 0150) = a source deck's stable key (`readers` · `chats` · `sentences` · `claude` · `explorer` · `practice` · `vr`; UNIQUE per user where set; `shared/decks/source-decks.ts`, docs/STUDY_SESSION.md "Source decks") — "+ Add as card" saves into these with no deck picker, found by key never by name
- `notes` - Vocabulary items (hanzi, pinyin, english, audio_url, fun_facts)
- `cards` - SRS cards (3 per note, one per card_type)
- `review_events` - Individual review records (rating, time, answer, recording_url). Card state is computed from these.
- `card_checkpoints` - Cached card state for performance (computed from review_events)
- `deleted_items` - Tombstones (`kind` deck|note, `item_id`, `deleted_at`) written whenever a deck or note is deleted (API routes, Ask Claude's delete_current_card, the MCP server's delete_deck/delete_note); `GET /api/sync/changes` returns them as `deleted.deck_ids` / `note_ids` so offline clients drop the rows (with their cards) on the next sync
- `graded_readers.queue_priority` - The reader queue ("Up next", migration 0140; `shared/reader/queue.ts`): NULL = never placed by hand (first, newest first); a move / reorder writes it on every unread ready story
- `reader_pages.words` / `reader_word_explanations` - Reader word chips (migration 0087): the page split into `{ text, pinyin, gloss }` segments (JSON), and Haiku's cached "More about this word" answers keyed by a hash of word + sentence; `reader_pages.words_checked` (migration 0148) = the version of the pinyin check the words went through (NULL = stored before it: the backfill checks + corrects them). See "Reader word chips"
- `char_explanations` - "More about 字" on the character sheet: Haiku's short card-independent explanation per character, shared by everyone (migration 0108). The dictionary itself is static (`worker/char-dict/`, see "Character sheet")
- `coach_conversations` / `coach_messages` = **the Claude thread store** (migration 0144; docs/CHAT.md "Claude threads"; ALL thread SQL in `services/claude-agent/store.ts`): every chat with Claude — Coach / Ask chats (`general`), Ask Claude on a card (`card`), practice chats (`practice`, read-only for now), Discuss with Claude (`chat_message`). Thread: `context_kind` / `context_ref` / `context_json` (descriptor + badge snapshot, never another person's user id), `client_id` (idempotent create), inbox `last_message_at` / `preview` / `unread`, `changed_at` (ISO ms, the `?since=` cursor), `summary` / `summary_upto` / `summary_at` (Claude memory, migration 0145: the thread's rolling summary), `language`, `tutor_visible` (NULL = account default), `read_only`, `archived_at`, `deleted_at` (tombstone), `source` / `legacy_id` (backfill keys). Message: `client_id`, `intent`, `auto_check`, `meta` (first_token_ms, total_ms, rounds, inline), `lease_until` (the runner writing the reply), `updated_at` (ISO ms), `legacy_id`. A reply being written stays `status = 'pending'` with the text so far in `content`. `users.claude_threads_backfilled_at` = the lazy per-user copy of note_questions / practice chats / message_discussions (`claude-agent/backfill.ts`). The Coach page lists only `general` threads
- `users.claude_tutor_visibility` - What the learner's tutor can read of his Claude chats (migration 0146; `shared/claude/visibility.ts`, docs/CHAT.md "What your tutor sees"): NULL / 'card_only' (default: card questions), 'all', 'none'; a thread's `tutor_visible` (1 / 0) wins. Learner Settings → Chat, `PUT /api/profile/claude-tutor-visibility`, on `/api/auth/me`
- `claude_learner_memory` - Claude memory (migration 0145; docs/CHAT.md "Claude threads" → "Memory", `services/claude-agent/memory.ts`): one row per learner — `digest` (≤ ~600 tokens: working on / keeps confusing / interests / level & preferences), `threads_index` (JSON, the 20 most recent chats with a one-line summary), `digest_at`, `watermark` (the newest thread `summary_at` folded in), `input_tokens` / `output_tokens` (every memory call so far). Read into every Claude chat's learner block; never the tutor's private profile
- `note_questions` - **FROZEN legacy table** (Nov 2026): the old one-row-per-Q&A store of Ask Claude (question, answer, asked_at; migration 0116 immersion columns). Nothing writes it any more — every card question lives only in its card thread (`coach_conversations` `context_kind = 'card'`); its rows reach the threads through the lazy backfill (`claude-agent/backfill.ts`, each message keeps the row id as `legacy_id`). The older row-shaped endpoints (`/api/me/claude-chats`, the tutor's `/claude-chats`, the card hub's `questions`, `/api/notes/:id/questions`, `/api/note-questions/:id*`, the legacy `POST /api/notes/:id/ask`) are served from the card threads (`claude-agent/card-questions.ts`). Only the admin account deletion still touches it
- `notes.word_tags` / `notes.word_tags_at` / `word_tag_runs` - AI word tags (migration 0120): the note's verdict (JSON `AiWordTags`, `shared/cards/word-tags-ai.ts`), when it last changed (synced like `check_at`), and per user the sync backfill's hourly window (`window_start`, `window_count`, `checked_at`) + tagged count and tokens. See "Word tags on the answer side"
- `notes.image_key` / `image_source` / `image_status` / `image_hash` / `image_at`, `note_images`, `decks.illustrate_new` - Pictures on cards (migration 0123; docs/STUDY_SESSION.md "Pictures on cards"): the note's picture (R2 `note-images/<hash>` generated — one per prompt hash in `note_images`, shared by every note asking for it — or `note-uploads/<note>-<id>` uploaded), drawing state, `image_at` synced like `word_tags_at` (never `updated_at`); the deck's "Illustrate new cards" switch (off by default)
- `notes.check_issues` / `notes.check_at` / `users.card_check` / `deck_check_jobs` - Word checks (migration 0104): open "⚠ Possible issue"s on a note (JSON, `shared/cards/check.ts`), when they last changed (synced like `long_term_at`), the "Check new words" switch (NULL = on for tutors), and per-deck "Check for errors" runs (deck, the deck's owner, relationship + source deck for a tutor checking a student's copy, status, progress, proposals JSON, tokens). See "Word checks"
- `audio_lessons` - Audio lessons (migration 0046 reused + 0111; docs/AUDIO_LESSONS.md): format dialogue|sleep|story (TEXT, no CHECK), status queued/writing/speaking/rendering/ready/failed, progress + clips done/total, input, the agent transcript, plan, script, timeline (chapters + transcript), words, `audio_key` (R2 `audio-lessons/`), usage, pinned `zh_provider`, `for_relationship_id` (a label only). Rows with `format` NULL are the removed first attempt
- `podcast_subscriptions` / `podcast_feed_cache` / `podcast_episodes` / `podcast_episode_users` - 🎙 Podcasts (migration 0125, docs/PODCASTS.md; Lab app only for now): a user's subscribed RSS feeds, the parsed feeds (shared, 30 min), ONE shared transcription per episode (id = hash of feed + guid; status queued → downloading → transcribing → translating → ready | failed, the R2 copy `podcast-episodes/<id>.<ext>`, Soniox job id, `segments_json` = `{ i, start_ms, end_ms, text, speaker, lang, pinyin, english }[]`), and who asked for which episode + the mini lesson made from it
- `watch_videos` / `watch_video_users` - 📺 Watch (migration 0158, docs/WATCH.md): ONE transcript per YouTube video for everyone (id = the video id; title, channel, duration, status queued → transcribing → translating → ready | failed, `chunks_done` / `chunks_total`, `chunks_json` = the per-window checkpoint with each window's raw Gemini lines, `lines_json` = `WatchLine[]` `{ i, start_ms, end_ms, zh, pinyin, english, speaker }`, provider / model, `usage_json` with `cost_usd`, `requested_by`), and who added / opened which video with their resume `position_ms` and `last_opened_at`. No YouTube media is ever stored
- `audio_lesson_feedback` - Feedback while listening (migration 0157; docs/AUDIO_LESSONS.md "Feedback while listening", `shared/audio-lesson/feedback.ts`): one row per "Too hard" / back a section / next section press on an audio lesson (client id, kind too_hard|again|back_section|skip, `source` lock_screen|notification|player|headset, position, chapter / row index, `row_json` + `previous_row_json` = the row playing and the one before, speed, audio version, created / received); `POST /api/audio-lessons/:id/feedback`, `GET /api/me/audio-lesson-feedback`, MCP `get_audio_lesson_feedback`
- `podcast_feeds` - The private podcast feed of a user's audio lessons (migration 0112): one row per user, `token_hash` (SHA-256, how a feed request finds the user), `token_enc` (AES-GCM, so Settings can show the link again), created / rotated / last fetched, fetch count. Reset = new token; Turn off = row deleted
- `card_flags` - A student flags one card for their tutor with a note (relationship, student, tutor, note, card, message, status open/resolved, tutor_reply, student_seen_reply_at). Migration 0070. See "Card flags & card hub" below
- `note_sentences` - Every example sentence of a note (position, hanzi, pinyin, translation, audio_url, focus, explanation, `is_card`): the card's own sentence is the row `<note id>-card` (`is_card = 1`, position −1, migration 0154 — kept in step with the deprecated `notes.sentence_clue*` by `db/card-sentence.ts`), then the generated set (0..n). `/api/sentences/changes` hands out whole notes + `note_ids`; synced to IndexedDB / Room for offline study. "Has a set" = a row with `is_card = 0`.
- `note_sentences.pinyin_checked` - The pinyin check version a row's pinyin + cached breakdown went through (migration 0156, NULL = not yet; `services/sentence-pinyin.ts`, see "Pinyin check on lessons and readers")
- `note_sentence_jobs` - Tracks which notes have been queued for background sentence-set generation (status, attempts)
- `clips` / `clip_events` - 🎬 Clips (migration 0137, docs/CLIPS.md): one row per clip in its owner's account (status ready/generating/failed, source agent/generated/manual, title / topic / theme, `spec` JSON per `shared/clips`, the generation `request` + progress / error / tokens, the clip's one mini lesson `lesson_status` / `lesson_id`), and the learner's events (view / complete / like / unlike / save / unsave / skip / double_tap / quiz / learn_more / interact — an interactive scene settled, value wrong 0 · right 1 · close 2 · done 3 · skipped −1; client ids, idempotent)
- `idioms` - 成语 Idioms (migration 0115, docs/IDIOMS.md): ONE generated entry per idiom for every account, keyed by the normalised hanzi (status generating/ready/failed/not_idiom, `entry` JSON per `shared/idioms`, error, suggestion, attempts, generator_version, view_count). No user ids
- `quests` - Generated tile-map mini-games (title, difficulty, status, `world` JSON, best_moves)
- `picture_hunts` / `picture_hunt_plays` - Picture hunts (migration 0082): source upload|generated, prompt, deck_ids, `image_key` (R2 `picture-hunts/<id>.<ext>`, protected — personal photos), size, status generating/ready/error + `progress`, `objects` JSON (`shared/picture-hunt`), best_found / play_count (recomputed from plays); plays are client-id rows (found_ids, hints_used, gave_up, duration)
- `custom_lessons` - Agent-authored custom mini lessons (`spec` JSON per shared/lesson; status active/done). `library_item_id` / `assigned_by` / `assigned_relationship_id` link a student's copy back to the tutor's library item
- `custom_lesson_completions` - Idempotent offline completion events for custom lessons (the rating sets when it comes back)
- `revisit_events` - Legacy "Done for good" / "Bring back" on a mini lesson (migration 0110; item_kind lesson|reader, item_id, action retire|restore, client id): a retire (until a restore) = done forever in the revision rule (`shared/study/lessonRevision.ts`); still accepted from old apps. `users.revisit_settings` = legacy gaps + `new_lessons_per_day` (read by nothing since Oct 2026; older builds get fixed defaults, `LEGACY_REVISIT_SETTINGS` in `services/revisit.ts`)
- `custom_lesson_completions.outcome` - a mini lesson run's outcome JSON `{ keys, missed }` (migration 0133): decides done forever vs a revision in a week (`shared/study/lessonRevision.ts`); NULL = derive from the attempt (same id) / a legacy rated finish
- `lesson_answer_checks` - Claude's check of a self-assessed lesson answer, cached for everyone by SHA-256 of `answerCheckCacheText` (migration 0127; no user ids). See "Claude checks your answer" in docs/STUDY_SESSION.md
- `lesson_images` - describe_image pictures, ONE per scene description (`prompt_hash` = SHA-256 of the normalised `image_prompt`, status pending/ready/failed, `image_key` = R2 `lesson-images/<hash>.<ext>`, attempts, error). Migration 0079. See "Lesson pictures" below
- `custom_lesson_attempts` / `custom_lesson_attempt_media` - Per-exercise answers + time of a lesson run (id = the completion event id, spec snapshot, `data` JSON per `shared/lesson/attempt.ts`) and the recordings made in it (R2 key, transcript). Migration 0074
- `lesson_library` - A tutor's master copies of mini lessons (spec, tags, version, archived_at)
- `editor_chats` / `editor_chat_messages` - Per-user Claude side-chat for an editor target (`target_type` 'lesson' | 'library' | 'reader', extensible); messages keep a spec snapshot and, for assistant turns, the proposed spec + accepted/rejected status
- `invites` - Invite links / email-bound invites for new sign-ups (the id is the bearer token in `/join/<id>`; created_by, email, inviter_role, share_deck_ids, max_uses/use_count, expires_at, revoked_at)
- `invite_redemptions` - Which user redeemed which invite (idempotent by pair)
- `access_requests` - Uninvited Google sign-in attempts (email, attempts, status pending/approved/dismissed) for the admin to approve
- `tutor_note_jobs` - Session-notes agent jobs (relationship, tutor, student, notes, priority, auto_share, status queued/running/done/failed/cancelled, progress, `steps` JSON, `transcript` JSON checkpoint, rounds, `result` JSON, error). Migration 0072. See "Session notes → homework agent"
- `assignments` / `assignment_events` - Homework (migration 0073, docs/HOMEWORK.md): what (`kind` deck|lesson|reader + the student's copy `target_id`), `mode` one_off|fsrs|both, `due_date` (student's calendar day), `item_ids` (a deck part's notes), split `part_index/part_count`, `status`/`done_count` recomputed from the student's pass events (right|wrong|done|undo|skip, idempotent by id); `skipped_at` = the student's live "Skip this homework" (migration 0139; the tutor sees "Skipped by <student>", §3d). NOT the legacy reader-only `homework_assignments` (0024, unused)
- `homework_links` - A tutor's link homework (migration 0102; docs/HOMEWORK.md §8): title, url, instructions, thumbnail_url (YouTube's public thumbnail only), soft `deleted_at`. Made in HER account, sent as an `assignments` row `kind: 'link'` whose `details` JSON keeps a snapshot `{ url, instructions, thumbnail_url }`; `assignment_events.note` = the student's note back on `done`
- `student_profiles` - The tutor's PRIVATE profile of a student, one per `tutor_relationships` row (tutor_id, student_id, markdown `body` ≤ 8000, optional `level` / `handwriting` / `words_per_lesson`). Migration 0077. Only the tutor-only route, the dashboard's `has_profile` flag and the tutor-side content agents read it — never a student-facing path. See "Student profile" below
- `study_bumps` - "⚡ Study it today" (migration 0106; `shared/decks/bumps.ts`, `services/study-bumps.ts`): one row per user + note the learner bumped to the front of today's study (id = client id, source, `bumped_by` = the learner or their tutor, created_at, `done_at` written lazily by the server once every bumped card was reviewed since the bump, `cleared_at` = taken out by hand). Active = both NULL; `/api/sync/changes` carries the active list as `bumps`
- `up_next` - "Up next" (migration 0121; `shared/decks/up-next.ts`, `services/up-next.ts`, docs/STUDY_SESSION.md "Up next"): the account's ORDERED list of notes introduced first within the daily budget — one row per user + note (id = client id, `position` 0..n-1, source, `added_by` = the learner or their tutor, created_at, `done_at` written lazily once every card of the note has a review, `removed_at` = taken off by hand; the note is never touched). Active = both NULL; `/api/sync/changes` carries the active list as `up_next`
- `card_holds` - Suspend & snooze (migration 0135; `shared/decks/holds.ts`, `services/card-holds.ts`, docs/STUDY_SESSION.md "Suspend & snooze"): one row per hold on a card (id = client id, `kind` 'suspend' | 'snooze', `until` = the LOCAL date a snooze ends, created_at, `cleared_at` = Unsuspend / Wake now). Never a review event or a state write — the queue leaves held cards out. `users.bury_siblings` = "Don't show a word's other card types on the same day" (NULL / 0 = off). `/api/sync/changes` carries the active list as `card_holds`
- `learner_structures` - Per user, the grammar structures met in his done mini lessons (migration 0151, JSON + a fingerprint `stamp`, rebuilt lazily by `services/learner-structures.ts`); the sentence generator asks for sentences using a few of them and tags each in `note_sentences.structure` (docs/STUDY_SESSION.md "Fresh sentences every showing")
- `sentence_practice_events` - Practice per example sentence (migration 0138; `shared/study/sentenceHistory.ts`, `services/sentence-practice.ts`, docs/STUDY_SESSION.md "Sentence practice history"): one row per event (id = client id, note, `sentence_key` = set row id or `clue`, `kind` attempt | hide | unhide | heard (played on a listening card's "Listen in context", mode `listen_context` — no migration), mode read | translate | listen (Hard mode's "Sentences by ear"; no CHECK on the column, so no migration), result right | close | wrong, reason, `at`, `received_at` = the sync cursor). Every device folds them (`sentenceStats`): the Sentence round prefers the sentences he knows least, hidden ones never come; `GET|POST /api/me/sentence-practice`
- `card_forgets` - "Forget this card" (migration 0136; shared/scheduler forget events, `services/card-forgets.ts`, docs/STUDY_SESSION.md "Forget"): one row per reset to New (id = client id, card, `forgotten_at`, source, `undone_at` = Undo). Merged into a card's events only to replay its state — never a review, so no count / streak / stat sees it. `/api/sync/changes` carries the live list as `card_forgets`
- `folders` - Folders for organising decks, Lesson Library items and graded readers (migration 0105; `shared/folders`, `services/folders.ts`): user_id, `kind` deck|lesson|reader, name (≤ 60), `parent_id` (folders nest up to 5 levels, `MAX_FOLDER_DEPTH`; no cycles), `position` (among siblings). Items carry a nullable `folder_id` (`decks`, `lesson_library`, `graded_readers`; NULL = Unfiled). Organisation only — the study queue never reads them. Deleting a folder unfiles its own items and lifts its subfolders ONE level (into its parent); nothing else is deleted. Copies made for a student never carry the tutor's folder_id
- `users.day_rollover_hour` - "New day starts at" (migration 0149; 0–6, NULL = 4 am): the study day's rollover hour (`shared/study/studyDay.ts`, `services/study-day.ts`); `PUT /api/profile/day-rollover`, on `/api/auth/me` + `/api/sync/changes`; every "today" of study on both apps and the server's per-user day (dashboard, review load, progress, e-mails) follow it
- `users.card_state_version` / `card_state_cursor` / `card_state_repaired_at` / `card_state_checked_at` / `card_state_last_fixed` - The server's card-state replay per user (migration 0153; `services/card-state.ts`): which repair version replayed every card (NULL = on the next queue read), where an unfinished run stopped, when it finished / was last re-checked (daily), how many rows the last run rewrote
- `users.sentence_style` / `note_sentences.style` - "Example sentence style" (migration 0155; standard | everyday | casual, NULL = everyday; `shared/study/sentenceStyle.ts`, docs/STUDY_SESSION.md "Example sentence style"): the register NEW example sentences are written in (the note owner's, read by the sentence-set generator); each new row records the style it was written in. `PUT /api/profile/sentence-style`, on `/api/auth/me` + `/api/sync/changes`
- `users.skip_handwriting` - "Skip handwriting exercises" (migration 0139, NULL / 0 = off; `PUT /api/profile/skip-handwriting`, on `/api/auth/me` + `/api/sync/changes`; shared/lesson/handwriting.ts, docs/STUDY_SESSION.md "Skip handwriting")
- `users.conversation_audio` - Conversation audio preferences JSON (migration 0110; `shared/lesson/conversationAudio.ts`, docs/AUDIO.md "Conversation audio")
- `users.voice_gender` - 'male' | 'female' | 'other' | NULL: the voice this person's chat messages are read aloud in (migration 0098; Profile → "Your voice when your messages are read aloud", admin `PUT /api/admin/users/:user/voice-gender`, MCP `admin_set_user_voice_gender`). See "Chat read-aloud voice"
- `users.new_card_order` - "Order new cards by" (migration 0113): JSON `NewCardOrder` (new_characters_first / new_words_first / most_common_first / sentences_last), NULL = every switch on (`shared/decks/new-card-order.ts`, `services/new-card-order.ts`)
- `users.study_budget_set_by` / `study_budget_set_at` - who last changed the daily new-card budget (the learner or their tutor) and when (migration 0097)
- `users` profile columns (migration 0076): `google_name` / `google_picture_url` (Google's last values), `name_custom`, `picture_source` (google|upload|none), `picture_key` (R2 avatar), `about` (public About me), `time_zone` (IANA). See `/profile` under Frontend Routes
- `study_time_days` - Active study time per user, local date and device (`active_ms`, only ever raised; migration 0083). Written by `PUT /api/me/study-time` (`routes/study-time.ts`); a day's total is the sum over devices. See docs/STUDY_SESSION.md "Time"
- `users.mcp_revoked_at` - epoch ms of the last "Sign out of all devices" (migration 0147): MCP OAuth grants made before it are refused and revoked by the MCP worker
- `lesson_requests` - ＋ Add tab → 🎯 Mini lesson (migration 0152; `services/lesson-requests.ts`, docs/ADD_TAB.md): one row per "make me a lesson about…" (user, prompt, status generating/ready/failed, `lesson_id` = the custom_lessons row in his account, error), written on coach-reply-queue (`{ kind: 'lesson_request', jobId }`) by the library's lesson writer
- `rate_limit_counters` - The cost guard's hourly job counter per user (migration 0128; key `jobs:<user id>`, epoch-hour window, count; `middleware/cost-guard.ts`)
- `feature_requests` - Feature requests AND in-app feedback (docs/FEEDBACK.md): content, page_context, console_logs, screenshot_url, status, approval_status, ccr_session_url, agent_session_url; migration 0142 adds `kind` ('request' | 'feedback' | 'bug'), `client_id` (POST /api/feedback is idempotent by user + client id), `context` (JSON per `shared/feedback`: platform, app version, route pattern, device, online, recent event names) and `screenshot_key` (R2 `feedback/<user>/<id>.<ext>`, private: author + admins). `feature_request_comments` = the thread
- `usage_events` - Usage analytics (migration 0100, docs/ANALYTICS.md): client + server events (id, user_id, ts, received_at, platform, app_version, session_id, event, screen = route pattern, props JSON of ids / enums / counts only); pruned after 180 days; `users.analytics_opt_out`
- `tts_settings` - The admin's TTS provider settings (migration 0107): ONE row (id 1), `settings` JSON per `shared/tts/config.ts`, updated_at / updated_by; no row = the defaults
- `debug_reports` - Index of study-state debug reports (migration 0075): user, client lab|web, app_version, install_kind, `r2_key` (the JSON is in R2 `debug/<userId>/<id>.json`), size, `summary` JSON; pruned to the newest 20 per user + client. See "Debug reports" below
- `recording_checks` - The background check of each pronunciation recording (migration 0109; docs/RECORDING_REVIEW.md): transcript + match, Azure score, per-character `char_scores` JSON, `score_note`, `audio_ms` / `scored_at` (free-tier budget)
- `tutor_relationships` - Tutor-student pairings (requester, recipient, role, status)
- `conversations` - Chat threads within a relationship: ONE per tutor–student pair (migration 0102 merged the extras, `merged_into` = the chat an old id became, unique index on live human rows); Claude practice chats may be several
- `messages` - Individual chat messages
- `messages.forwarded_from` - the source message of a forward (migration 0095)
- `messages.system_kind` / `system_data` - System messages (migration 0132, docs/CHAT.md "System messages", `shared/chats/system.ts`, Lab `core/…/chat/SystemMessages.kt` parity-tested): lines the platform posts on someone's behalf (`study_budget`, `call_started`, `card_flag`, `flag_reply`, `install_howto`, `group_class`) — the person stays the sender, the apps draw a centred muted row in the third person from the viewer's side (`systemMessageView`), `content` = the recipient's third-person fallback for older apps / e-mail / push. Every server path that posts on someone's behalf goes through `postSystemMessage` (`services/chat/system.ts`)
- `messages.album_id` / `album_index` / `album_notified_at` - photo albums (migration 0118, docs/CHAT.md "Photo albums"): photos picked together share the album id (client-chosen), their 0-based index, and the one photo that sent the album's notification
